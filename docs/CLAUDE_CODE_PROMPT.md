## ゴール
既存の Python 採点パイプライン（jv_export.py / score_horse_v3.py / build_dashboard_v3.py / build_review.py / run_new.py ほか）を**バックエンドのエンジンとして再利用**し、その上に Web アプリを構築する。詳細要件は docs/APP_BUILD_METAPROMPT.md の「要件」「役割分担」「機能要件」に従う。要点:
- 管理者機能: 予想/回顧ダッシュボード生成、メモ馬管理、的中精度検証、買い判定の妙味検証。
- ユーザー機能: 予想/回顧の閲覧、オッズ手入力によるEV(妙味)判定、メモ馬の閲覧・編集。
- PC/スマホ両対応（レスポンシブで同一アプリ、GUIのみ最適化）。

## 厳守ルール（docs/RULES_AND_NOTES.md より）
- **コードや構成を変更する前に、必ず設計・影響範囲を提示して承認を得る**。承認前に実装しない。
- ユーザーは非エンジニア。説明は日本語・簡潔に。
- **物理削除はしない**（不要物は _archive へ移動 or 削除スクリプトをユーザーが実行）。ユーザー許可なく欠損値を都合よく解釈しない。
- 既存採点仕様を必ず踏襲: 16因子・P3/P4採用、地方馬の参考扱い＋最低クラス丸め、順位予想からの地方除外、買い目軸=勝率cap(MR=3.0)後1位(≠スコア1位)、速報系(RT_)フォールバック。
- **モデルは市場に妙味では勝てない（検証済）**。妙味検証は「監視・確認」用で収益前提ではない旨をUIに明記。
- .bat は ASCII 専用、CSV は cp932、race.db はローカル(Windows)・COM依存。

## 進め方（フェーズごとに設計提示→承認→実装）
1. リポジトリ構成とAPI雛形を提案（既存スクリプトの副作用のないサービス化から）。
2. 公開閲覧: races一覧＋pred/review表示＋オッズ入力EV再計算（読み取りのみ）。
3. メモ馬: 閲覧/編集API＋UI（memo_horses.json 互換）。
4. 管理生成: 更新/エクスポート/採点/回顧のトリガとステータス表示。
5. 検証: 的中精度検証・妙味検証の集計画面。
6. レスポンシブ仕上げ＋ロール分離＋公開。
