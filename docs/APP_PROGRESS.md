### フェーズ4: 管理生成
- 管理タブ ①データ更新 → ②レース選択 → ③馬場 → ④予想を作る → ⑤確認して公開 →
  ⑥結果を取り込む → ⑦回顧 → ⑧検証データ作り直し。
- **バッチの書き換えが不要に**: `run_review_today.bat` / `run_regen_today.bat` は日付・会場・
  レース番号がべた書きで毎回手編集が必要だった。画面で選んだレースを使う形に置き換え。
- **JRA馬場の自動取得**: ページのHTMLには数値が入っておらず（JavaScriptが後から描画）、
  これが従来の取得失敗の原因だった。ページが読みに行くデータ配信URL
  （`_data_cushion.html` / `_data_moist.html` / `_data_week.html`）を直接取得する方式に。
  3会場ぶんがまとめて入っており、`title` 属性で会場を特定するので開催場が変わっても追従する。
  取得値は**そのまま保存せず、確認・修正してから** `baba_manual.json` へ。
- **SmartRC の rcode を race.db から自動生成**（例: 2026/07/25 札幌7R → `2026072501010107`）。
  不安定な `races/view` を呼ばないので、rcode を手で調べる作業が不要に。
- 速報系の対象開催日を自動設定（当日・前日のときだけ `setting.xml` を触る。公式コマンド経由・
  変更前バックアップあり）。
- 生成と公開を分離（`run_new.py` に `--no-publish` / `--publish` を追加。承認済み・追加のみ）。
- 回顧の状態を自動判定（未作成／速報のまま作り直せる／確定待ち）。
- JV-Linkキーの有効化はGUI操作のため自動化不可 → 実行前チェックリスト＋`RC=-303` の明示。

## 解決済みの確認事項

- **6月の回顧は作成済みだった**（2026-07-27 ユーザー指摘 → 修正）。
  pred/review HTML には3種類の命名が混在しており、中間形式
  （`20260620_hs11_Open_TenpouzanS_review.html` / `20260621_hs12_2_review.html`）を
  拾えず「未作成」と誤判定していた。`app/backend/services/paths.py` を修正し、
  回顧未作成の件数は **74件 → 20件** に是正（残りは7/26の17件＋4月の3件）。
  `app/tests/test_paths_naming.py` で3種類の命名を固定。

- **障害戦は採点の対象外**（2026-07-27 ユーザー指摘 → 修正）。
  検証タブの「馬場別」「芝ダ別」に出ていた `?` は障害戦（TrackCD 51〜59）だった。
  芝・ダートの基準タイムが無いため採点できないのに、除外されていなかった。3層で対策。
  - `jv_export.py`: 障害を「芝」とみなす既定値を廃止し、エラーで停止
  - `racedb.predictable_races()`: 予想候補の一覧から除外（管理②で選べなくなる）
  - `validation._match()`: 検証の集計から除外
  影響は軽微（対象 9,694R→9,480R、軸複勝 49.76%→49.96%）。
  障害戦のダッシュボードは過去に一度も生成されていなかった（手作業で避けられていた）。

- **会場コード表の誤り**（2026-07-27 発見 → 修正）。
  `run_new._VENUE_CODE_MAP` が `NK` を新潟としていた（正しくは**中山**。
  `20260321_NK11R` フラワーカップ＝中山で確認）。`OK`(小倉)は未登録だった。
  さらにメモ馬の自動登録が独自の変換表を持っており、`sp/fs/hd/kk/ng` を変換できず
  `HS` を浦和としていた。表を一本化し、`app/tests/test_venue_codes.py` で固定。

- **メモ馬のレース情報を補正**（2026-07-27 ユーザー承認のうえ実施）。
  原因（上記2件）を直したうえで、既存627件を `app/tools/fix_memo_race_info.py` で補正。
  会場77件・レース名481件・クラス481件。馬名/登録日/メモ本文は無変更。
  会場そのものが違う3件は、race.db で**馬名＋日付を照合し、出走が1件だけかつR番号が
  一致する場合のみ**修正（推測での書き換えはしない）。
  控えは `_archive/app_backups/memo_horses_*_before_fix.json`。

- **含水率はゴール前・4コーナーの両方を保存する**（2026-07-27 ユーザー要望）。
  `baba_manual.json` に `含水率_芝_4コーナー` / `含水率_ダート_4コーナー` を追加保存。
  採点（トラックバイアス）が読むのは従来どおり `含水率_芝` / `含水率_ダート`（＝ゴール前）で、
