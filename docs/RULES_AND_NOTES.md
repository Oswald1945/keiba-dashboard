# RULES_AND_NOTES — 共通ルール・注意事項

## 共通ルール（厳守）
1. **コード変更前に必ず内容を説明し、承認を得てから実装する。** 影響範囲・取り込みイメージを先に提示。
2. **破壊的操作（物理削除）はしない。** 不要ファイルは `_archive/` へ移動、または削除スクリプトを用意してユーザーが実行。ユーザーの明示許可なく欠損値を勝手に許容/都合よく解釈しない。
3. **ユーザーは非エンジニア。** 回答は日本語・簡潔。手順は「どのバッチをダブルクリック」レベルまで具体化。パス(`/sessions/...`)等の内部表現をそのまま見せない。
4. **`.bat` はASCII専用**（rem含め日本語不可＝CP932文字化け）。CSV入出力は cp932。
5. **馬場(良/稍重/重/不良)は採点に強く効く**ので、画像読み取り値は書き込み前にユーザー確認。
6. 変更後は必ず構文チェック（`python -c "import ast; ast.parse(open(f).read())"`）と、可能なら実データでの動作確認。高stakesは差分/スクショで検証。

## データ取得の注意（JV-Link / race.db）
- **race.dbはサンドボックス未マウント**。Claudeは直接クエリ不可。確認系はスクリプトを用意しユーザーが実行。
- データ取得前に **JV-Link設定→OK**（キー確認）。怠ると RC=-303。
- **当日結果は速報系(RT_)**。蓄積系(NL_)確定は翌日以降。速報系有効化は `setting.xml` の `JVRealTimeDataUpdateSetting/IsEnabled=true` ＋ 対象開催日(`JVKaisaiDateKey/KaisaiDate`)を当日に設定 → `-m exec`。
- 速報系は `RT_` テーブルに入る（NL_とは別）。パイプラインは「NL_に無ければRT_を読む」フォールバック実装済（jv_export/check_results）。
- 1角/2角を通過しないコース距離では `Jyuni1c/Jyuni2c=0`。**0は未通過=None扱い**（build_review `_pass_pos`）。
- レースラップ(`LapTime`/`HaronTimeS3`/`HaronTimeL3`)は確定成績に載る。速報で未配信ならペース系は「速報回顧では取得不可」表示、翌日確定で `--review --force`。

## 採点ロジックの注意
- **目的は精度**（軸複勝率・順位相関）。ROI/妙味は市場に勝てない前提（別レイヤーの道具）。
- 地方(NAR)馬: JRA歴あれば JRA走のみ採点／無ければ地方走で採点し `地方実績のみ`＋格を未勝利相当に丸め。参考バッジ・買い目軸/EVから除外・順位予想は後方。
- 買い目軸＝**勝率cap(1/オッズ×MR, MR=3.0)後の勝率1位**（≠スコア1位）。人気薄の過剰評価抑制。差があればダッシュボードに注記。
- P3(相対上がり)・P4(成績重み付きコース適性)採用済。P1(線形devブレンド)はrank保存で不採用。
- 新馬・未勝利は精度検証外。

## 運用の注意
- 生成物は `done/` へ移動される（pred/review完了後）。`run_regen_today.bat` は再exportで input/ に戻す。
- GitHub Pages公開時の「CRLF will be replaced by LF」警告は無害。
- サンドボックスbashは cwd継承なし・timeout最大45s・独立実行。長時間処理は<45sに分割。

## 品質・検証
- 変更は原則: ①設計提示→承認 ②実装 ③構文OK ④実データ検証 ⑤ユーザー確認。
- 高stakesな変更（データ整合・欠損扱い）は網羅的にチェックし、誤読・都合の良い解釈をしない。
