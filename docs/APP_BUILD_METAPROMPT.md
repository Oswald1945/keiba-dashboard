## ロール
あなたは競馬データアプリのフルスタック実装者。既存の Python 採点パイプライン（`jv_export.py`/`score_horse_v3.py`/`build_dashboard_v3.py`/`build_review.py`/`run_new.py` ほか）を **バックエンドのエンジンとして再利用** し、その上に管理機能とユーザー機能を持つ Web アプリを構築する。ゼロから採点ロジックを作り直さない。

## ゴール
1. **予想ダッシュボード**と**回顧ダッシュボード**の生成を、会場・レースを選ぶだけで完結する管理UIから実行できるようにする（現状のバッチ手順をGUI化）。
2. **メモ馬管理**、**予想の的中精度検証**、**買い判定の妙味検証** を管理者機能として実装する。
3. **ユーザー機能**: 予想/回顧ダッシュボードの閲覧、オッズ手入力による妙味(EV)判定、メモ馬の閲覧・編集。
4. **PC/スマホ両対応**（レスポンシブで同一アプリ、GUIのみ最適化）。

## アーキテクチャ方針（推奨・確定は着手時に提案し承認を得る）
- **バックエンド**: Python（FastAPI 推奨）。既存スクリプトを関数/サービスとして呼ぶ薄いラッパAPIを作る。`race.db`(SQLite) は読み取り、生成物(JSON/HTML)を配信。
  - 管理API: `/admin/update`(JV-Link更新トリガ), `/admin/export`(会場/レース選択→CSV生成), `/admin/predict`(採点→pred), `/admin/review`(回顧), `/admin/validate/accuracy`, `/admin/validate/value`。
  - 公開API: `/races`(一覧), `/race/{id}/pred`, `/race/{id}/review`, `/race/{id}/ev`(勝率＋オッズ入力でEV再計算), `/memo`(GET/PUT)。
- **フロント**: レスポンシブSPA（React 推奨、または既存HTMLテンプレの資産化）。PC=多カラム、スマホ=1カラム/カード。既存 `build_dashboard_v3.py`/`build_review.py` のUI（枠色・バッジ・EVシミュレータ・買い目提案・コーナー通過チャート）をコンポーネント化して継承。
- **JV-Link連携**: JV-Link(COM)はWindows専用。管理API実行時にローカルの `jvlink_update.ps1`/`jvlinktosqlite` を子プロセス起動する形にする（サーバはユーザーのWindows上で動く前提）。
- **状態/データ**: `baba_manual.json`・`memo_horses.json`・生成物JSON はファイルベースを維持（既存資産と互換）。将来DB化は任意。
- **認証**: 管理/ユーザーのロール分離（最小実装でよい。ローカル運用なら簡易トークンやローカルのみ管理ルート可）。

## 機能要件の詳細
### A. 管理: ダッシュボード生成の自動化
- 会場・レースを画面で複数選択（`predict_select.py` のロジックをAPI化）。予想/回顧を1操作で。
- 進捗表示（各レースの採点/生成/公開ステータス）。エラー時は該当レースを明示。
- 馬場入力フォーム（`baba_manual.json` を編集）。天候・クッション値・含水率も。
- SmartRC取り込み（手動アップロード or 自動取得トライ）。

### B. 管理: 的中精度検証
- 既存の `validate_accuracy.py`/`build_review.py` の的中・順位相関・KPIを、期間/会場/クラス/馬場で集計。
- 指標: 軸複勝率、予想上位N的中率、順位相関、キャリブレーション。**精度が主目的**（ROIではない）。

### C. 管理: 買い判定の妙味検証
- 既存 `bet_recon.py`/`roi_backtest.py`/`bet_backtest.py` を使い、券種フォーメーションの的中/回収を確定配当(`NL_HR_PAY`/`RT_HR_PAY`, `haraimodoshi_*.json`)で照合。
- **注意**: 妙味は市場に勝てないことが検証済（`モデル検証_総括_20260723.md`）。この機能は「監視・確認」用であって収益前提ではない旨をUIに明記。

### D. ユーザー: 閲覧＋EV判定＋メモ
- pred/review をレスポンシブ表示。オッズ手入力で単勝/複勝EVと買い目採算オッズを即時再計算（既存 `EV_DATA` + softmax + 勝率cap ロジックを踏襲）。
- メモ馬の一覧・追加・削除・メモ編集（`memo_horses.json`）。回顧からの自動抽出も統合。

## 既存ロジックで必ず踏襲する仕様（詳細は各mdへ）
- 16因子採点、P3/P4採用、地方馬の参考扱い＋最低クラス丸め、順位予想からの地方除外。
- 買い目軸＝勝率cap後1位（≠スコア1位）。MR=3.0。
- 速報系(RT_)フォールバック（当日結果/払戻/脚質/ペース）。ペース未取得は「速報回顧では取得不可」。
- `.bat`はASCII、CSVはcp932、race.dbはサーバ(Windows)ローカル。

## フェーズ計画（各フェーズ着手前に承認）
1. **足場**: リポジトリ構成・API雛形・既存スクリプトのサービス化（副作用のない読み取りから）。
2. **公開閲覧**: races一覧＋pred/review表示＋EV再計算（読み取りのみ、まず動くものを）。
3. **メモ馬**: 閲覧/編集API＋UI。
4. **管理生成**: 更新/エクスポート/採点/回顧のトリガとステータス。
5. **検証**: 精度検証・妙味検証の集計画面。
6. **レスポンシブ仕上げ＋ロール分離＋公開**。

## 完了の定義
- 管理者が画面操作だけで「取得→採点→公開」「回顧公開」「精度/妙味検証」を実行できる。
- ユーザーがPC/スマホでダッシュボード閲覧・EV判定・メモ編集をできる。
- 既存の採点/回顧の数値が現行パイプラインと一致（回帰テストで担保）。
